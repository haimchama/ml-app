# ML – מערכת ניהול משרד עו"ד מיכאל ליטווק

מערכת ניהול למשרד: לקוחות ולידים, תיקים עם תהליך לפי סוג תיק, משימות, יומן מועדים, משתמשים ויומן פעולות.
נבנתה ומתוחזקת על ידי TKB. כתובת: https://ml.tkb-pro.com

## מבנה

| נתיב | מה זה |
|---|---|
| `public/` | הממשק: HTML/CSS/JS בלי שלב build, פונטים מקומיים (בלי בקשות לשרתים חיצוניים) |
| `src/worker.js` | ה-API ‏(`/api/*`) ב-Cloudflare Worker בשם `ml-app` |
| `src/db.js` | מיגרציות D1 (append-only, רצות לבד בבקשה הראשונה) |
| `src/lib.js` | ולידציה, תבניות תהליכים, הצפנת סיסמאות (PBKDF2) |
| `tests/` | `npm test` |

## הרצה מקומית

```
npm install
printf 'SETUP_TOKEN=any-local-token\nDEV_MAIL_LOG=1\n' > .dev.vars
npm run dev            # http://127.0.0.1:8787
npm test
```

`DEV_MAIL_LOG=1` כותב את קוד הכניסה ללוג במקום לשלוח מייל. **אסור להגדיר אותו ב-Cloudflare.**

## תפקידים

| תפקיד | מה מותר |
|---|---|
| IT – מנהל מערכת | הכל: משתמשים, הרשאות, מצב המערכת, ניתוק משתמשים, יומן פעולות, אישור לקוחות, כל היומנים |
| עורך/ת דין | אישור לקוחות, סגירת תיקים, פיקוח (משימות באיחור, יומן פעולות). רואה "הועבר לטיפולך" ואת היומן שלו |
| מזכירות | הזנת לקוחות ולידים (נכנסים לאישור עו"ד), תפעול תיקים ומשימות, ניהול היומן של כל עורכי הדין |

בכניסה הראשונה המערכת מבקשת קוד הקמה (SETUP_TOKEN) ויוצרת את משתמש המנהל. משם מוסיפים את שאר הצוות מתוך "משתמשים".

## הקמה ב-Cloudflare (פעם אחת, הבעלים)

1. D1 בשם `ml` (ה-`database_id` כבר ב-`wrangler.jsonc`).
2. לחבר את הריפו ל-Workers Builds כ-Worker בשם `ml-app`: production branch `release`, build `npm ci && npm test`, deploy `npx wrangler deploy`.
3. להגדיר secret בשם `SETUP_TOKEN` (קוד חד-פעמי להקמת משתמש ה-IT הראשון).
4. הכתובת `ml.tkb-pro.com` מוגדרת ב-`wrangler.jsonc` כ-custom domain ונוצרת בפריסה הראשונה.
5. **שליחת מיילים (חובה לכניסה):** ב-Cloudflare → Email Service → Email Sending, להוסיף את הדומיין `ml.tkb-pro.com` (או `npx wrangler email sending enable ml.tkb-pro.com`). זה מוסיף רשומות DNS רק לתת-הדומיין `ml`, לא ל-tkb-pro.com עצמו. הכתובת השולחת: `no-reply@ml.tkb-pro.com` (המשתנה `MAIL_FROM`).
   עד שזה מוגדר אי אפשר להיכנס למערכת (הקוד לא נשלח), בכוונה.

## פרסום

`main` לעבודה שוטפת. push ל-`release` מפרסם לאוויר.

## אבטחה ופרטיות

- כניסה דו-שלבית: סיסמה (10+ תווים, אותיות וספרות) ואז קוד חד-פעמי בן 6 ספרות שנשלח למייל, בתוקף 10 דקות, עד 5 ניסיונות ו-3 שליחות.
- נעילה אחרי 5 ניסיונות כושלים (סיסמה או קוד) ל-15 דקות.
- שינוי תפקיד, השבתה או איפוס סיסמה מנתקים את המשתמש מכל המכשירים.
- עוגיית סשן HttpOnly + Secure + SameSite=Strict, תוקף 12 שעות; הטוקן נשמר במסד רק כ-hash.
- בדיקת Origin ו-Content-Type בכל בקשה שמשנה נתונים, CSP קשיח, בלי סקריפטים או פונטים חיצוניים.
- כל פעולה נרשמת ביומן הפעולות (למנהלים).
- אין אנליטיקס, פרסומות או SDK חיצוני. הנתונים נשמרים ב-Cloudflare D1 בחשבון של TKB.
